## 1. 目前真正知道什么

现有P0/grib_provenance.json确认data/CERRA/dacdd4252851172d1e8fbd4b4def733a.grib的风速覆盖2024-01-01 00:00至2024-12-31 21:00，共2928条。项目data/CERRA当前可见的主要GRIB和已验收空间CSV为这一年份，尚未发现已验收的2025/2023数据。文件名本身不能证明年份；也没有扫描项目外目录。

官方单层目录提供CERRA高分辨率三小时分析场，以及不同提前量的预报场，两者不能混用。参考：https://cds.climate.copernicus.eu/datasets/reanalysis-cerra-single-levels 。目录的时间覆盖不代表本地文件或每个请求已完整下载。

候选优先2025，以便在2024开发之后的年份复现；2023为按数据可用性考虑的备用。使用2023仍是未用于开发的回溯年份确认，不是向未来年份迁移。最终年份只能根据覆盖完整性/产品一致性决定，不能根据新年份误差或RS收益决定。2025若性能不好，不能换到2023重新宣称第一次确认成功。

## 2. 新数据如何准备

在官方目录选择与现有输入匹配的10m wind speed、高分辨率、analysis、00/03/06/09/12/15/18/21 UTC，GRIB格式，优先全年；保留原请求、下载回执、文件大小及后续SHA256。不要改成gust、ensemble、forecast的valid_time混合数据，也不要为本轮新增温度/气压/方向。

为保持原网格索引和外围偏移，首轮维持同一原生网格/扫描方向。若下载服务空间裁剪或重网格改变了网格，不能直接复用旧center_y/center_x和偏移；需额外证明真实坐标映射与邻域完全等价，首轮建议避免这一变化。所有新文件存项目内独立年份目录，如data/CERRA/raw_2025/，不覆盖2024。

完整非闰年2025应有2920个三小时风速时刻，2024闰年为2928。三个28天测试窗口之外，还必须具备对应60天训练和28天验证历史。只下载4/7/10月不够。

## 3. 元数据审计：先不看预测误差

已实现audit_newyear_headers.py及slurm/run_newyear_audit.sh。新文件到位后，从根目录手动提交：

```bash
sbatch slurm/run_newyear_audit.sh
```

默认只清点项目data/CERRA内所有*.grib；有多个重叠下载时，建议显式传入最终选定文件，多个文件以空格分隔：

```bash
sbatch slurm/run_newyear_audit.sh --grib data/CERRA/raw_2025/实际文件名.grib
```

这里第二条的文件名是占位示例，不是当前存在的文件。如果尚无新数据，不必为了重证已有2024而急于重复清点。

每项1线程、4GB、1小时；日志logs/newyear_audit_JOBID.out/.err，结果result/newyear_audit/headers_JOBID/inventory.json与completion.json。脚本仅遍历GRIB头，不解码风场数组、不训练、不读取模型误差。

检查参数207、10m高度、m/s、analysis/step=0/instant、与原GRIB一致的投影/格距/网格尺寸/地球定义/扫描方向；逐年记录匹配消息、缺测、重复、非三小时整点及不兼容消息。重复文件会报告重复时刻，禁止静默去重；应依据下载清单明确选择唯一来源。混有预报产品时要检查被排除消息与选择规则。headers_complete只表示匹配产品的时间轴完整，不是数据或实验READY。

当前只运行过两项合成测试（闰年/非闰年、缺测、重复、错年、错时刻），没有真实GRIB审计结果。

| 主要汇总 | 逐seed百分比收益→窗口内平均→三个窗口等权平均；不能只选夏季 |
